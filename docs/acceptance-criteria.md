# Mini-Kadrika — условия приёмки

**Статус: Draft · 25.11.2026.** Это предлагаемые критерии конечного продукта, не акт приёмки прототипа. Требуют согласования [требований](requirements.md) и [бизнес-правил](business-rules.md). Все backend-критерии ниже **не проверены**: Django и PostgreSQL в проекте отсутствуют.

## Доказательства и текущая проверка

Проведён статический анализ `c6bf957`: [сценарные тесты](../src/tests/scenarios.test.ts), [локальный API](../src/api/local.ts), [HTTP-адаптер](../src/api/http.ts), [storage](../src/api/storage.ts), страницы, providers, hooks и существующие docs. Наличие теста подтверждает только написанный сценарий, а не успешный запуск в этой работе.

25.11.2026 выполнена попытка `npm test`: **запуск не состоялся**, exit code 1, `vitest` не найден; зависимости не установлены. В окружении Node v26.13.0 / npm 11.20.0, тогда как README предлагает Node 24. Зависимости и исходный код в этой работе не менялись. Новые lint/typecheck/build, браузерные E2E и ручная демонстрация не выполнялись.

README сообщает о прежних 25 успешных тестах, [prototype-limitations.md](prototype-limitations.md) — о 23 на более раннем этапе. Эти исторические записи сохранены; они не являются актуальным протоколом приёмки. Даже успешный прогон local-тестов не доказывает серверную безопасность, транзакции и конкурентность.

В таблице «П» означает: часть сценария можно проверить на существующем прототипе; «Б» — требуется Django/PostgreSQL; «AI» — дополнительно выбранный реальный провайдер. **НП** = не проверено в этой работе, критерий не принят. Для строк П/Б локальная проверка не заменяет серверную. Ожидаемый результат явно указан в Then; значения 10/0 — предварительные тестовые условия A-02.

## Как применять комплект

Сначала согласовать открытые вопросы и обновить связанные FR/NFR/BR/AC. Затем реализовать backend и необходимые изменения frontend, прогнать интеграционные проверки на PostgreSQL и E2E, сохранить команды, окружение и результаты. Для AC-008/009/011/014/018/019 требуются управляемые конкурентные запросы через разные соединения; однопоточная имитация и SQLite не являются доказательством.

Статус критерия меняется на «проверен» только со ссылкой на фактический протокол/результат, а на «принят» — после согласования заказчиком. Сейчас ни один критерий конечного продукта не отмечен выполненным. Неопределённые контентные, нагрузочные и эксплуатационные пороги нельзя подменять произвольными числами ради успешного теста.
