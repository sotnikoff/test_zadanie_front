# Предложение функциональных границ MVP

Цель — провести демонстрацию заказчику, согласовать сценарии и выявить недостающие требования до разработки Python/PostgreSQL backend.

В прототип входят закрытый вход и роли USER/ADMIN; кабинет с балансом, завершёнными генерациями и чистым расходом; создание стихотворений по теме, пожеланиям, настроению и числу четверостиший; статусы и копирование; история генераций и неизменяемый журнал операций; административное создание пользователей, начисления и общие списки с фильтром по пользователю.

Генерация стоит 10 единиц, оплачивается при принятии, при ошибке единицы возвращаются. Повторная отправка не вызывает повторное списание. Данные сохраняются в браузере, работа двух пользователей демонстрируется последовательным переключением аккаунтов. Demo Tools дают управляемые задержки, сбой, переключение и сброс.

Оформление — светлый SaaS-интерфейс с боковой навигацией, верхним балансом и мобильным меню. Предусмотрены loading/empty/error состояния, уведомления, подтверждения и доступные диалоги.

Не входят: backend, настоящая база данных, реальный AI, платежи, подписки, тарифы, регистрация и восстановление пароля, редактор стихов, изображения/аудио/видео, социальные функции, организации и сложные права, очереди, WebSocket и аналитические графики.

На согласование после показа: точность и вариативность будущего AI, смысл внутренних единиц и политики начисления, способ выдачи/смены паролей, срок хранения истории, серверный процесс генерации и окончательный API. Ни одна из этих тем не считается согласованной реализацией production.

Критерии приёмки: сценарии из demo-scenarios воспроизводятся; история сохраняется; списание и возврат согласованы; USER не видит чужие данные через интерфейсы; ADMIN может создавать и начислять; local/http выбирается централизованно; typecheck, tests и build проходят.
