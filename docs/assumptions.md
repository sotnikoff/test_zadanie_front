# Принятые допущения

1. Используется выбранный заказчиком заполненный демо-набор. Анна и Александра: начисление 150, два успешных списания по 10, одно списание и возврат 10; баланс 130. Михаил: начисление 20 и одна успешная генерация; баланс 10. Начальные даты относительны первому запуску/сбросу.
2. ADMIN сохраняет пользовательские разделы и дополнительно получает административные. Создавать через UI можно только USER. Имя обязательно, пароль от 8 символов, email уникален без учёта регистра. Баланс нового пользователя — 0.
3. Одна генерация стоит 10 целочисленных единиц независимо от параметров. Чистый расход = списания минус возвраты; число созданных стихотворений учитывает COMPLETED.
4. Финансовая операция хранит сумму со знаком: CREDIT/REFUND положительные, DEBIT отрицательная. Поле balanceAfter фиксирует баланс в момент операции.
5. Запросы имеют requestId (UUID). Повтор совпадающего запроса возвращает прежний результат; повтор с другими параметрами отклоняется. Идемпотентность генераций ограничена пользователем, начислений — локальной базой.
6. По умолчанию задержка запросов 250 мс; генерация проходит PENDING, затем PROCESSING и заканчивается примерно через 2,5 секунды плюс получение результата. Без задержек фазы всё равно асинхронны. Случайных сбоев нет: ошибка включается в Demo Tools для следующего принятого запроса; отказ из-за баланса флаг не расходует.
7. Перезагрузка прерывает работу Mock AI: при новой инициализации PENDING/PROCESSING переводятся в FAILED с возвратом. StrictMode не создаёт второй runtime. Смена аккаунта не отменяет уже принятые генерации, их владелец не меняется.
8. Тема обязательна (1–120 символов), пожелания до 1000, настроение из шести значений, четверостиший от 1 до 4. Тема отображается заголовком. Только первое четверостишие зависит от настроения, дополнительные строфы универсальные. Пожелания сохраняются без семантической интерпретации.
9. Начисление требует положительного безопасного целого числа и непустого комментария до 300 символов. Проверяется также переполнение итогового баланса. Диалог начисления служит подтверждением; сброс имеет отдельное подтверждение.
10. Один браузер, одна активная вкладка; данные не синхронизируются между компьютерами. Сессия бессрочна до выхода/сброса. Отдельные демонстрационные credentials хранятся в инфраструктуре и не входят в User.
11. Предварительный REST использует cookie-сессию и polling; пагинация пока не предусмотрена. API, CSRF и настройки CORS предстоит согласовать с backend-командой.
12. Работа остаётся локальной. Git изначально отсутствовал; по отдельному запросу заказчика репозиторий инициализируется с первым коммитом.
