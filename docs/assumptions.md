# Принятые допущения

1. В текущей версии есть только пользовательский кабинет. Управление пользователями, роли и ручное начисление исключены по запросу заказчика. Самостоятельная регистрация отсутствует.
2. Начальный демо-набор: Анна — CREDIT 150, две успешные генерации по 10 и одна ошибка с возвратом; доступно 130. Михаил — CREDIT 20 и одна успешная генерация; доступно 10. Даты относительно первого запуска/сброса.
3. CREDIT сохраняется как тип исторической операции и используется при подготовке начального баланса. Через пользовательский API создавать начисления нельзя. Пополнение в прототипе недоступно.
4. Генерация стоит 10 безопасных целочисленных единиц; стоимость и проверка баланса находятся в src/api/local.ts. Чистый расход учитывает REFUND, число стихотворений учитывает только COMPLETED.
5. requestId (UUID) обеспечивает идемпотентность по пользователю. Изменение параметров с прежним ключом — конфликт. Повторный возврат исключён.
6. По умолчанию сетевые задержки 250 мс, генерация занимает около 2,5 секунд. Ошибки не случайны: подготовленные FAILED есть в истории, новые принудительные сбои проверяются через api.demo.failNext() в тестах. Demo Tools удалены из UI.
7. Перезагрузка незавершённой генерации переводит её в FAILED с возвратом. Смена сессии не меняет владельца принятого запроса.
8. Тема обязательна, до 120 символов; пожелания до 1000; шесть настроений; 1–4 четверостишия. Mock AI использует тему как заголовок, не интерпретирует пожелания, выбирает первую строфу по настроению, остальные — универсальные.
9. Схема v2 мигрирует v1 без сброса истории, балансов, credentials и сессии. У всех старых аккаунтов удаляется роль; служебный индекс ручных начислений больше не нужен. Финансовые операции остаются неизменными.
10. Один браузер и одна активная вкладка. Сессия сохраняется до выхода/сброса. Локальные credentials демонстрационные и не защищены от владельца браузера.
11. HTTP использует предварительную cookie-сессию и polling. API, CORS, CSRF, выдача аккаунтов и будущее пополнение требуют отдельного согласования. Backend не реализован.
12. Проект локальный; Git инициализирован по запросу заказчика.

13. По запросу заказчика архитектура упрощена: один интерфейс Api, обычные функции, локальные действия в одном файле. Первоначальное разделение Domain/Application/Infrastructure больше не применяется. HTTP оставлен отдельной реализацией для будущего backend.
