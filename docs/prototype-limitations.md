# Ограничения и проверки

Авторизация, контент, многопользовательская работа и финансовые операции являются демонстрационными имитациями. LocalStorage хранит credentials открыто для владельца браузера. Guard и проверка принадлежности записи не являются production-защитой.

Используется одна вкладка одного браузера. Единый снимок связанных изменений не обеспечивает ACID, блокировки и конкурентную многопользовательскую работу. При переполнении хранилища вызов возвращает ошибку без частичного сохранения. Незавершённые генерации от прежних версий восстанавливаются с возвратом при запуске. Новые локальные генерации выполняются сразу, без искусственных задержек и фоновых задач.

Управление пользователями и начисление средств удалены. Новые демо-данные содержат два обычных аккаунта. Существующие аккаунты и финансовая история сохраняются при миграции v1 → v2, но без ролей и служебного индекса начислений. Старые CREDIT остаются журналом фактически показанных операций. Средств для новых генераций в демо конечное количество; пополнения через приложение нет.

Mock AI использует подготовленные строфы и не интерпретирует пожелания. Тема — заголовок результата. Реальные AI API, платежи и backend не подключены.

HTTP-контракты предварительные; интеграция с реальным backend не проверялась. Unit-тесты с подставным fetch проверяют только клиент. Локальные тесты не подтверждают безопасность, конкурентность или транзакционную целостность будущего backend.

## Проверки текущей версии

Автотесты охватывают вход, генерацию/списание, недостаточный баланс, ошибку/возврат, повторный запрос, изоляцию пользователей, персистентность, восстановление, отказ хранения, выбор local/http, HTTP-ошибки и миграцию сохранённых данных. Административные тесты удалены вместе с соответствующим функционалом.

После удаления искусственных задержек выполнены: npm run lint — без ошибок и предупреждений; npm test — 23 теста проходят; npm run typecheck — успешно; npm run build — успешно. Проверены готовый результат за один вызов, списание и возврат, отсутствие частичного сохранения при ошибке записи, восстановление старых PENDING/PROCESSING и удаление прежней настройки задержек без потери данных.

Для backend требуется реализовать согласованные пользовательские API, серверную идентификацию, проверку принадлежности, транзакционное списание и возврат, идемпотентность и настоящую AI-генерацию. Выдача аккаунтов и пополнение должны согласовываться отдельно, за пределами текущего frontend. После этого — интеграционные, security и concurrency проверки и переключение VITE_DATA_SOURCE=http.

После упрощения архитектуры используются функции createLocalApi/createHttpApi вместо классов адаптеров. Схема хранилища и ограничения сохранены.
