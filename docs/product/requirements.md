# Требования к MVP

Рабочий проект до обратной связи заказчика. В прототипе реализована только локальная демонстрация; следующие требования относятся к будущему сервису.

## Цель и границы

Пользователь получает стихотворения и видит расход своих единиц. Оператор создаёт аккаунты, начисляет единицы и контролирует использование сервиса через Django Admin. Python задан заказчиком; Django, PostgreSQL и синхронный AI — выбранное направление реализации.

Вне MVP: реальные платежи, подписки, регистрация, самостоятельное восстановление пароля, другие виды контента, редактор стихов, отдельная административная SPA и фоновая очередь. Возврат по качеству и пользовательская отмена пока не предусмотрены.

## Функциональные требования

| ID | Требование |
| --- | --- |
| FR-001 | Вход по email/паролю, выход; блокировка аккаунта запрещает последующие защищённые запросы. |
| FR-002 | Пользователь видит только свои результаты, баланс и операции. |
| FR-003 | Тема, пожелания, настроение и 1–4 четверостишия; параметры проверяются до списания. |
| FR-004 | Перед запуском показаны серверная цена, баланс и остаток после списания. |
| FR-005 | Генерация через один OpenAI-совместимый API; результат или ошибка сохраняются. |
| FR-006 | Одно списание на принятый запрос; при окончательной технической ошибке — один возврат. |
| FR-007 | Повтор запроса не списывает повторно; после обрыва можно найти результат по requestId. |
| FR-008 | История, фильтр по статусу, просмотр параметров и копирование стихотворения. |
| FR-009 | Баланс, журнал операций, связи с генерациями и расход с учётом возвратов. |
| FR-010 | Django Admin: создание пользователя с балансом 0, смена пароля, блокировка. |
| FR-011 | Начисление оператором с суммой, комментарием и защитой от повторной отправки. |
| FR-012 | В админке — фильтры и простые итоги по генерациям, единицам и токенам, без графиков. |
| FR-013 | История хранит провайдера, модель, входные, выходные и общие токены; неизвестные значения — NULL. |
| FR-014 | Предусмотреть служебное завершение зависших генераций с однократным возвратом. |

## Требования к качеству

| ID | Требование |
| --- | --- |
| NFR-001 | Серверная проверка доступа, стандартные пароли/сессии Django, CSRF и HTTPS; секреты только на сервере. |
| NFR-002 | Неотрицательный баланс, атомарные операции и защита от повторов, включая одновременные запросы. |
| NFR-003 | Ограниченное ожидание AI; внешний вызов не удерживает транзакцию БД. |
| NFR-004 | Воспроизводимый запуск backend и БД, миграции и сохранение данных после перезапуска. |
| NFR-005 | Логи ошибок и автора начисления без секретов; проверка восстановления резервной копии перед рабочим запуском. |
| NFR-006 | Нагрузка, время ответа и бюджет AI согласуются до реализации backend. Числовых обещаний пока нет. |
| NFR-007 | Понятные состояния ожидания/ошибки, запрет повторной отправки, работа с клавиатуры и на мобильном экране. |

## Вопросы для согласования

Пока принимаем: стартовый баланс 0, цена 10, единицы неделимы (масштаб 1:1), техническая ошибка компенсируется полностью. Дробные суммы отклоняются без округления. Детальные правила — [business-rules.md](business-rules.md).

| ID | Вопрос |
| --- | --- |
| Q-01 | Подтверждается ли предложенный объём, кто будет оператором? |
| Q-02 | Как выдавать и восстанавливать доступ, какие права и срок сессии нужны? |
| Q-03 | Подтверждаются ли баланс 0 и цена 10? Каковы основания/лимиты начислений и правила исправлений? Нужны ли отмена и возврат по качеству? |
| Q-04 | Какой провайдер и модель, что считать пригодным стихотворением? Кто предоставляет ключ? |
| Q-05 | Как долго ждать AI и когда считать запись зависшей? Кто и в какой срок выполняет компенсацию? |
| Q-06 | Ожидаемая нагрузка, лимиты запросов и бюджет AI; кто оплачивает внешние расходы? |
| Q-07 | Где размещать сервис, сколько хранить данные, нужны ли удаление/выгрузка и какие сроки восстановления допустимы? |
| Q-08 | Какие итоги и часовой пояс нужны оператору? |
| Q-09 | Нужны ли дробные единицы, например цена 0,5? Если да, какая точность и округление? Пока единицы неделимы; переход потребует изменения масштаба и миграции. |

После обратной связи уточним объём и оценку: [следующие шаги](next-steps.md). Критерии проверки: [acceptance-criteria.md](../testing/acceptance-criteria.md).
