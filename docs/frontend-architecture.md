# Архитектура frontend

## Границы

`src/modules` содержит auth, generations, billing. Domain экспортирует типы сущностей; общие связанные frontend-модели собраны в shared/types для исключения циклических зависимостей. Application/ports описывает прикладные асинхронные операции. Дополнительные use-case классы не введены: в данном MVP они лишь дублировали бы вызовы портов.

Infrastructure/local имитирует backend, Infrastructure/http реализует те же порты через HttpClient. Presentation содержит страницы и hooks. Application и UI не списывают и не начисляют средства. Агрегация истории для отображения вынесена в billing/domain/summary.

## Композиция

`src/app/composition` создаёт один набор Gateways. Конфигурация проверяется на старте. В local создаётся один LocalDatabase и один LocalRuntime, разделяемые адаптерами. В http создаётся общий HttpClient. React Context внедряет готовые порты. DemoGateway остаётся только локальным инструментом тестовых сценариев и признаком доступности демо-аккаунтов на странице входа; панель Demo Tools удалена. В http этот порт отсутствует. Отдельные страницы не анализируют VITE_DATA_SOURCE.

TanStack Query получает данные через порты, обрабатывает состояния запросов и инвалидирует зависимые данные. Ключи пользовательских запросов включают userId. Выход/смена аккаунта очищают кэш. Маршрут Guard проверяет сессию; локальные адаптеры повторно проверяют доступ к каждой операции.

## Локальное хранение и генерации

LocalDatabase использует StoragePort для тестирования и LocalStorage в браузере. Схема v2 хранится единым JSON под mini-kadrika:db. Пустое хранилище получает seed. Неизвестная версия/повреждение показывают экран восстановления без автоматического удаления; сброс требует подтверждения. Версия v1 автоматически мигрирует в v2: сохраняются все аккаунты, credentials, кошельки, операции, генерации и сессия; поле role и индекс ручных начислений удаляются. В новой модели User ролей нет.

update клонирует текущее состояние, применяет изменение, сериализует и сохраняет одним setItem. Внутренняя копия меняется только после успешной записи. При исключении не публикуется частично изменённое состояние. Это не блокировки, не ACID и не поддержка нескольких вкладок.

Генерация: в одном update проверяются requestId/баланс, создаются PENDING и DEBIT. Runtime ставит локальный таймер, обновляет PROCESSING и выполняет MockAIProvider. Завершение сохраняет результат либо вызывает compensate, которая записывает FAILED и REFUND единожды. Повторный запрос не запускает вторую задачу. После перезагрузки recover компенсирует незавершённые записи. Сброс останавливает таймеры.

Получение конкретной генерации проверяет владельца. Порта общих списков и управления аккаунтами больше нет. Учётная запись, принявшая запрос, остаётся владельцем даже при смене текущей сессии.

## HTTP

HttpClient передаёт credentials, JSON, Base URL, различает сетевые ошибки и HTTP-ошибки, проверяет ожидаемые поля ответов через декодеры. Полноценная схема согласованного API ещё отсутствует. Ошибки выходят как AppError(code, message), сообщения выводятся интерфейсом без HTML-интерпретации. Автоповторы мутаций отключены.

Для реального backend: реализовать предварительные контракты, согласовать аутентификацию/CORS/CSRF, серверную стоимость и идемпотентность, заменить мок настоящей генерацией, протестировать интеграцию и пересобрать с http. Менять presentation для самого переключения источника не требуется.
