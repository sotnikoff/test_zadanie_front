# Сценарии демонстрации

Обновление интерфейса: панель Demo Tools убрана по запросу заказчика. Ниже сохранены исходные сценарии; действия через эту панель сейчас недоступны в UI. Смена аккаунта выполняется через выход и вход; принудительный сбой и компенсации проверяются автоматическими тестами.

Начинать с нового хранилища или Demo Tools → Сбросить демо-данные → подтверждение. Сброс удаляет созданные локальные данные.

1. **Вход:** выбрать Анна на странице входа, нажать Войти. Начальный баланс 130, два готовых стихотворения, чистый расход 20. Неверный пароль показывает ошибку. Меню профиля позволяет выйти.
2. **Успех:** Генерация → заполнить тему, пожелания, настроение и число четверостиший. Проверить цену 10, текущий баланс и прогноз. Запустить: кнопка блокируется, открывается запись с состоянием обработки. Затем появляется текст и копирование; баланс 120. В истории операций появляется DEBIT -10.
3. **Сбой:** Demo Tools → Вызвать ошибку следующей генерации. Создать новую генерацию. После обработки статус FAILED, сообщение о возврате, баланс совпадает со значением до запуска. В журнале есть DEBIT -10 и REFUND +10 по одному ID.
4. **Недостаток:** начать со сброса, войти Михаилом (10 единиц). Выполнить одну успешную генерацию. Следующая недоступна, форма показывает нехватку средств. Новое списание не создаётся.
5. **Перезагрузка:** включить задержку, запустить и немедленно перезагрузить страницу во время обработки. После старта приложения запись FAILED, баланс восстановлен, возврат один. Повторная перезагрузка не увеличивает баланс. Готовые результаты и сессия сохраняются.
6. **Изоляция:** создать стихотворение Анной, переключиться на Михаила. В личной истории видны только его записи; прямой URL чужого результата показывает «Генерация не найдена». Административный URL для USER возвращает на главную.
7. **Администратор:** переключиться на admin, открыть Пользователи. Создать USER с именем, уникальным email и паролем от 8 символов. Начальный баланс нулевой. Начислить 50 с комментарием, подтвердить; баланс и журнал изменяются. Проверить запрет дробной/отрицательной суммы и дубликата email.
8. **Обзор:** открыть административные Генерации и Денежные операции, выбрать пользователя, посмотреть результат через запись или связанную операцию. Список пользователей можно искать по имени/email.
9. **Мобильный интерфейс:** на ширине около 390 px открыть меню, перейти в историю и баланс. У таблиц есть горизонтальная прокрутка, формы занимают ширину экрана.
10. **HTTP:** указать VITE_DATA_SOURCE=http, перезапустить Vite. Demo Tools и подсказки демо-входа отсутствуют. Без сервера ожидается ошибка сети, а не успешная авторизация. Реальную интеграцию проверять только после реализации согласованного API.

Автотесты отдельно воспроизводят идемпотентность, отказ сохранения, восстановление, права, целочисленные суммы и HTTP-ошибки. UI не предоставляет кнопку повторного возврата или прямое редактирование журнала.
