# Мини-Кадрика

Интерактивный прототип сервиса создания стихотворений. Он помогает согласовать пользовательские сценарии, правила списания внутренних единиц и границы MVP перед разработкой backend.

## Как запустить

Установите Node.js 24 и выполните в папке проекта:

```sh
npm ci
cp .env.example .env
npm run dev
```

Откройте [localhost:5173](http://localhost:5173). Если порт занят, используйте адрес из терминала. Для демонстрации сервер и API-ключи не нужны.

## Тестовые пользователи

На странице входа выберите аккаунт и нажмите «Войти». Пароль для всех — `demo1234`.

| Пользователь | Email | Начальный баланс |
| --- | --- | ---: |
| Анна | user@example.com | 130 |
| Михаил | user2@example.com | 10 |
| Алексей | user3@example.com | 0 |

Кнопка **«Сбросить демо-данные»** на странице входа после подтверждения удаляет изменения всех аккаунтов и восстанавливает начальные балансы и историю. У Анны и Михаила есть примеры генераций; у Алексея история пустая. Обычное обновление страницы данные сохраняет.

## Что реализовано в прототипе

Пользователь входит в готовый аккаунт, создаёт стихотворение, копирует результат, просматривает свою историю, баланс и операции. Стоимость генерации — **10 единиц**. Перед запуском показаны цена, баланс и ожидаемый остаток. При недостатке единиц запуск недоступен; при сбое предусмотрен возврат.

Тема обязательна, пожелания необязательны. Доступны шесть настроений и от одного до четырёх четверостиший. Локальная генерация выполняется сразу, без искусственных задержек. Периодического опроса статусов (поллинга) нет: после генерации интерфейс обновляет баланс, операции и историю, затем открывает результат.

В прототипе пока нет backend, административного раздела, создания пользователей, начисления единиц и реального AI. Ниже описан следующий этап — работающий многопользовательский MVP. Реальные платежи, самостоятельная регистрация, подписки, редактор стихов и генерация других видов контента остаются за его пределами.

## Сценарии прототипа и критерии приёмки

| Сценарий | Условия и действия | Ожидаемый результат |
| --- | --- | --- |
| Вход | Ввести данные тестового аккаунта | Открывается главная, виден баланс пользователя. После обновления страницы сессия сохраняется. |
| Ошибка входа | Ввести неверный пароль | Появляется сообщение об ошибке; вход не выполнен. |
| Создание стихотворения | Баланс не ниже 10. Заполнить тему, выбрать настроение и длину, нажать «Создать стихотворение» | Открывается текст нужной длины. Баланс уменьшается на 10, в истории появляются генерация и связанное списание. |
| Незаполненная форма | Оставить тему пустой и попытаться отправить форму | Генерация не запускается, единицы не списываются. |
| Недостаток единиц | Войти Алексеем или потратить последние 10 единиц Михаила | Запуск недоступен, показана причина. Баланс не становится отрицательным. |
| Повторный запрос | Повторно отправить тот же запрос с тем же идентификатором | Возвращается прежний результат без второго списания. Проверяется автотестом. |
| Сбой генерации | Имитировать ошибку через тестовый API | Сохраняются статус ошибки, списание и один возврат. Итоговый баланс не меняется. В интерфейсе нет кнопки вызова сбоя; пример есть в начальной истории Анны. |
| История и копирование | Открыть историю, выбрать статус и готовое стихотворение, нажать «Скопировать» | Видны подходящие записи, параметры и текст выбранного результата. При разрешённом доступе к буферу текст копируется. |
| Баланс и операции | Открыть раздел «Баланс» после генерации | Показаны текущий остаток и операция −10 со ссылкой на результат. История операций недоступна для редактирования. |
| Сохранение данных | Создать стихотворение и обновить страницу | Результат, списание и новый баланс сохраняются. |
| Выход и смена пользователя | Выйти через меню профиля и войти другим аккаунтом | Открываются данные другого пользователя. Чужой результат по прямой ссылке недоступен; без входа защищённые страницы перенаправляют на логин. |
| Сброс демо | Выйти, нажать «Сбросить демо-данные» и подтвердить | Новые генерации удалены, балансы восстановлены до 130 / 10 / 0. Отмена подтверждения сохраняет изменения. |

## Демонстрация за 5–10 минут

1. На странице входа сбросить демо-данные, чтобы начать с известного состояния.
2. Войти Анной. Показать главную, баланс 130 и примеры стихотворений.
3. Создать стихотворение на тему «Первый снег», выбрать настроение и две строфы. Показать результат и баланс 120; скопировать текст.
4. Открыть историю и баланс: найти новую запись и списание −10. Обновить страницу и показать, что данные сохранились.
5. Открыть начальную неуспешную генерацию Анны и связанный возврат в журнале операций.
6. Выйти и войти Михаилом. Создать одно стихотворение: баланс меняется с 10 на 0, следующая генерация недоступна.
7. Войти Алексеем. Показать пустую историю и запрет генерации при нулевом балансе.
8. Выйти, сбросить демо-данные и снова войти Анной: баланс 130, созданного на показе стихотворения нет.

## Проверки

Последние выполненные проверки кода: `npm run lint` — без ошибок и предупреждений; `npm test` — **25 тестов прошли**; проверка TypeScript и `npm run build` — успешно. Эта редакция README не меняет код приложения.

| Область | Что проверено или предстоит проверить |
| --- | --- |
| Автотесты локального API | Вход и ошибки, генерация и списание, нехватка единиц, возврат без дублирования, разделение данных пользователей, сохранение и сброс, нулевой баланс, загрузка старых данных и отказ хранения. |
| Автотесты HTTP-слоя | Выбор режима, запросы и обработка ошибок с подставными ответами. Реальный backend не подключён. |
| Ручная проверка ранее | Вход, создание стихотворения, списание, сохранение результата после обновления и связанная операция. Работа списания также подтверждена заказчиком. |
| Перед передачей заказчику | Пройти маршрут демонстрации на финальной версии; отдельно проверить копирование, подтверждение и отмену сброса, клавиатурную навигацию и мобильную ширину. Полная ручная приёмка не зафиксирована. |
| После подключения backend | Проверить реальную интеграцию, серверные права доступа, одновременные запросы и согласованность списаний и возвратов. |

## Что прототип не позволяет проверить

Прототип не подтверждает серверную безопасность, корректность одновременных списаний, восстановление после сбоев сервера, качество и стоимость реального AI, производительность и резервное копирование. Работа оператора в Django Admin и полезность предложенной аналитики также потребуют проверки на следующем этапе. Тесты локальной эмуляции не заменяют эти проверки.

## Устройство и ограничения

Интерфейс написан на React и TypeScript. Локальная эмуляция и сохранение находятся в `src/api`; данные хранятся в LocalStorage браузера. Для показа используйте одну вкладку: аккаунты, авторизация и денежные операции демонстрационные, настоящая конкурентная работа пользователей не реализована. Пароли доступны владельцу браузера, единицы не являются деньгами.

Стихи собираются из готовых строф. Тема служит заголовком, пожелания сохраняются, но не интерпретируются. Локальные тесты не подтверждают безопасность и транзакционную целостность будущего backend.

Для подключения backend нужно актуализировать предварительные [API-контракты](docs/architecture/api-contracts.md) под синхронный ответ генерации, согласовать их и реализовать серверную авторизацию, генерацию и учёт единиц. Затем задать в `.env` значения `VITE_DATA_SOURCE=http` и `VITE_API_BASE_URL` с адресом сервера и перезапустить приложение. Сейчас по умолчанию используется `local`; реальная интеграция ещё не проверялась.
